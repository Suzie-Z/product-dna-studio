# Product DNA Studio

An English-only experience-to-infographic studio, with a stateless OpenAI API backend and a free static frontend.

## Current experience

1. Click **Create your DNA**.
2. **Share your experience** using text, a CV (PDF/DOCX/TXT, max 5 MB), or browser voice transcription. Successful uploads show a check, failed uploads a red cross with a retry button. Extracted text remains editable.
3. **Generate my Product DNA** calls the server-side OpenAI Responses API. Loading, provider errors and retry states are visible. There is no keyword fallback or fabricated demo result.
4. The output shows 1–4 evidence-based journey stations and 2–4 strengths in a high-resolution infographic, with a neutral walking explorer character. English labels, short summaries, fit-to-box rendering and verified source quotes support readability and grounding.
5. **Save image** exports a 2000×1400 PNG. **Edit & regenerate** returns to the original input; changing input hides the outdated result. There is no separate manual card editor.

The neutral character and scene are deterministic vector illustrations, not a separate image-model call for every user. Journey and DNA content are generated by the LLM. This keeps text crisp, export reproducible, and per-generation cost lower.

## Source files and build

- `preview/studio.template.html`, `studio.css`, `studio.js`: interface source.
- `preview/poster.js`: high-resolution canvas renderer.
- `build_preview.py`: bundles all local assets into `preview/index.html` for the existing static hosting command.
- `ai_server.py`: stateless Python 3.11+ API, standard library only.
- `test_ai.py`: schema, evidence, provider contract and access tests; all provider calls in tests are mocked.

After editing frontend sources, run:

```sh
python build_preview.py
python -m unittest test_ai -v
node --check preview/studio.js
node --check preview/poster.js
```

The API service deploys the `ai-experience` branch; the static site deploys `main`. Keep both branches aligned when changing API code. Commit both sources and the generated `preview/index.html`. The existing Render static site copies only that bundled HTML to its publish directory. Do not publish the repository root.

## AI configuration

Create an API key in an OpenAI API project with an appropriate billing setup. ChatGPT subscription and session tokens do not provide API credit. Never paste keys into chat, frontend source, or the repository.

On the Render **product-dna-studio-ai** service, open **Environment**, add `OPENAI_API_KEY`, and choose **Save and deploy**. `OPENAI_MODEL` defaults to `gpt-5-mini`. The server uses structured output and `store: false`; OpenAI's separate retention and abuse-monitoring policies still apply. Check current model availability/pricing before changing the model. This implementation uses the GPT-5 reasoning parameter and must be adapted before choosing a non-reasoning model.

When the key is missing, the backend remains healthy but generation returns an explicit 503 message. Live model behavior cannot be verified until the owner configures a funded key.

## Trial controls and privacy

- This app does not persist CV text, voice transcripts, generated results or visitor profiles. They live in the browser and request memory. Refreshing loses the draft and image.
- Browser speech recognition retains the spoken language. A voice-language selector controls recognition where supported; the model translates the output into English. Voice support and transcription quality depend on the browser and its speech provider.
- PDF/DOCX parsing happens in the browser using CDN libraries. Scanned PDFs need OCR and are rejected if no text is readable. PDFs are limited to 15 pages. Input is limited to 16,000 characters.
- The API validates output structure, field lengths, English display labels and literal evidence quotes. It rejects unsupported/incomplete results; evidence quotes are returned with structured results but not printed in the infographic.
- `DAILY_GENERATION_LIMIT=10` caps provider requests per running process per Australia/Sydney calendar day, including failed provider requests. **This is a best-effort request cap, not a verified limit of ten unique people. It resets if free compute restarts.** A strict paid-call budget or visitor quota requires durable counters and identity/invites. Set a separate budget in the OpenAI project and monitor usage; do not rely on this in-memory cap alone for cost enforcement.
- Set `TRIAL_START_DATE=YYYY-MM-DD` when the owner decides to launch the public trial. With that value set, the API permits seven calendar days using Australia/Sydney dates. No launch date is set by default; the public-trial clock has not started.
- CORS allows the current static frontend and the backend's own origin. Origin checks are not identity/authentication; the shared endpoint must remain low-volume until durable abuse controls are added.
- Free Render compute can sleep and cold-start. The UI waits up to three minutes; there is no background warming or paid disk. Static hosting remains on its included usage tier. OpenAI API calls are billed separately.
